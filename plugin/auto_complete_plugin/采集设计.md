# 浏览器原型采集与补环境设计笔记

日期：2026-11-02 创建，2026-11-08 更新

> 2026-11-08：浏览器 Plugin / MimeType 运行时实现已从框架移除；`AutoResult/Plugin*.json`、`MimeType*.json` 快照仍保留，供以后按需再生成，不参与当前运行时。

## 1. 目标与原则

从真实浏览器采集某个原型的全部自有属性及其描述符，输出 JSON 快照；再把快照解析成可插入框架的 JS 代码，统一补环境文件的形状。

两条原则：

- **形状**（属性是否存在、descriptor、name/length/toString）→ 快照预生成，必须对齐
- **逻辑**（getter/setter 的实际行为）→ 等 target 调用时再补，命中驱动

工程原则：

- **采集端只读**，probe 不修改环境；所有伪装/保护（safefunction、toString、symbol）放在生成端
- **生成区域只负责形状**，手写逻辑写在区域外覆盖，保证可重复生成

## 2. 当前插件结构

```

  Analysis.js          # 单条快照记录 -> 一段生成代码

  AutoResult/

```

职责拆分：

| 文件 | 职责 |
|---|---|
| `probe.js` | `Reflect.ownKeys` + `getOwnPropertyDescriptor`，输出纯 JSON 快照 |
| `collector.js` | 启动系统 Chrome，替换 `__TARGET__`，`page.evaluate`，落盘 |
| `Analysis.js` | `parse(item, targetExpr)` 生成一段代码；提供 `HELPERS` |
| `main.js` | 快照检查/采集、遍历、拼接、区域替换、语法检查、写文件 |

`collector.js` 导出：

```js
const { AutoComplete } = require("./collector");
await AutoComplete("Node.prototype");
```

- 使用系统 Chrome：`channel: "chrome"`
- 默认有头；`PROBE_HEADLESS=1` 切无头
- probe 末尾用 `__TARGET__` 占位符
- 输出：`AutoResult/<target>.json`

## 3. 采集探针

核心顺序：

```js
for (const key of Reflect.ownKeys(target)) {
  const d = Object.getOwnPropertyDescriptor(target, key);
  if (!d) continue;

  if ("value" in d) {
    if (typeof d.value === "function") {
      // 方法 / constructor
    } else {
      // 常量 / 普通值 / 对象值
    }
  } else {
    // accessor
  }
}
```

规则：

- 用 `Reflect.ownKeys`，同时覆盖字符串键和 symbol 键
- **只取 descriptor，不读属性值**
- 用 `"value" in d` 分 data / accessor，不要只用 `typeof d.value`
- 常量不能做真值判断：`0`、`""`、`null`、`false` 都会丢
- accessor 的 get/set 名字自带 `get ` / `set ` 前缀
- symbol 键转成 `keyName` 字符串，另记 `keyType`
- 结果用数组保存，保持顺序
- 函数只记 `name` + `length`；生成时交给 `__autoFn` 伪造。传了第三参数（手写 impl）时，`__autoFn` 会用方法简写把 impl 包一层，保证产物的 own keys 只有 `length` / `name`、没有 `prototype`、不能被 `new`，和原生 getter / 方法一致

### 3.1 对象值处理

`typeof d.value === "object"` 时不能原样塞进 JSON，否则会遇到：

- `JSON.stringify(Node.prototype)` → `TypeError: Illegal invocation`
- Playwright 返回时把 DOM 对象降级成有损的普通对象副本
- 循环引用、体量爆炸、身份丢失

`valueInfo` 的规则：

| 类型 | 编码 |
|---|---|
| 函数 | `{ name, length }` |
| `null` / number / string / boolean | 原值 |
| `undefined` | `{ type: "undefined" }` |
| symbol | `{ type: "symbol", text }` |
| bigint | `{ type: "bigint", value }` |
| 普通对象 / null 原型对象 | `{ type:"object", tag, proto, entries }` |
| 宿主对象（DOM、WindowProxy、prototype） | `{ type:"object", tag, manual:true }` |

普通对象的 `entries` 只浅展开一层：子函数记 name/length，子对象只记 tag，accessor 记 `<accessor>`。

### 3.3 实测结果

| 目标 | items | accessor | constant | function | manual |
|---|---:|---:|---:|---:|---|
| `Element.prototype` | 155 | 92 | 2 | 61 | 无 |
| `NodeList.prototype` | 9 | 1 | 1 | 7 | 无 |
| `Location.prototype` | 2 | 0 | 1 | 1 | 无 |
| `Document.prototype` | 248 | 186 | 2 | 60 | 无 |
| `location`（实例） | 16 | 10 | 1 | 5 | 无 |
| `Node`（构造函数） | 21 | 0 | 21 | 0 | `prototype` |

说明：

- `Location.prototype` 只有 `constructor` + `Symbol.toStringTag` 是真实情况；Location 的成员是 `[LegacyUnforgeable]`，挂在 `location` 实例上
- `Node` 构造函数的 `prototype` 是宿主对象，标记为 `manual`，不能复制
- `location[Symbol.toPrimitive]` 在 Chrome 里是 data 属性，值为 `undefined`

## 4. 生成端 Analysis.js

API：

```js
const { parse, HELPERS } = require("./Analysis");
const code = parse(item, "Node.prototype");
```

- `parse(item, targetExpr)`：一条快照记录 → 一段代码字符串
- `HELPERS`：`__autoFn` 辅助函数，main 在每个生成块前放一次
- 也导出 `keyExpr` / `valueExpr` 便于调试

生成规则：

- **方法 / accessor**：`__autoFn("get innerHTML", 0)`；函数体首次命中时执行 `debugger`，由 `__autoHit` 按 name 去重
- **常量**：原始值、`BigInt(...)`、`undefined`
- **普通对象**：`{ ["after"]: true }` 或 `Object.assign(Object.create(null), {...})`
- **symbol 键**：`Symbol.toStringTag` 等表达式，动态映射所有 well-known symbol
- **对象字面量键**：统一用计算属性，避免 `__proto__` 触发原型 setter
- **constructor**：输出 `// TODO constructor` 注释，不生成空壳
- **manual 宿主对象**：输出 `// TODO manual: <key> (<tag>)`

生成样例：

```js
// innerHTML
Object.defineProperty(Element.prototype, "innerHTML", {
    configurable: true,
    enumerable: true,
    get: __autoFn("get innerHTML", 0),
    set: __autoFn("set innerHTML", 1),
});
```

`__autoFn` 工厂本身不在调用栈上。带手写 impl 的会多一层同名包装帧（形状对齐原生 getter 的代价）：impl 抛错时 `e.stack` 比原生多一帧；vm2 下 `CallSite.getFunction()` 返回 null，拿不到代理背后的 impl，包装前对原始函数登记 `csvm.safefunction` 是兜底。

包装层通过加载时抓的 `const __autoApply = Reflect.apply;` 调 impl，目标之后替换 `Function.prototype.apply` / `Reflect.apply` 影响不到框架内部调用。

## 5. main.js 编排与区域替换

当前流程：

1. 检查 `AutoResult/<TARGET>.json`，不存在则调用 `AutoComplete(TARGET)`
2. 读取 JSON
3. `records.map(item => parse(item, TARGET)).join("\r\n")`
4. 拼 `HELPERS`，包进 IIFE
5. `new Function(block)` 做语法检查
6. 替换目标文件区域，写回

区域标记：

```js
/* #region AUTO:Node.prototype */
(function () {
    function __autoFn(name, length) { ... }
    Object.defineProperty(Node.prototype, "nodeType", { ... });
    ...
})();
/* #endregion AUTO:Node.prototype */
```

- 首次用 `/*补齐占位*/` 插入
- 之后用 START / END 标记整块替换，保证幂等
- `replace` 用函数替换，避免生成代码里的 `$` 被当成替换模式
- 写入路径是完整的 `TARGET_FILE_PATH`

注意：

- 手写逻辑必须写在 **END 标记之外**，否则重新生成会被覆盖
- `constructor` 必须在 `csvm.proxy(...)` 之后手写，才能保证 `Proto.constructor === Ctor`
- 生成器目前会为 `getElementById` / `createElement` 生成空壳，手写实现需要在区域外覆盖；后续可加 skip 列表

## 6. 当前限制 / 待办

1. **constructor 未生成**：所有原型都只有 TODO，需手写
2. **构造函数 `prototype` 标记 manual**：必须指向真实原型，不能复制
3. **函数自身元信息未采**：`name` / `length` 的 descriptor 按标准写死；`Reflect.ownKeys(fn)` 和 toString 原文未采
4. **safefunction symbol 泄漏**：生成的所有函数带自定义 symbol，框架侧待改 WeakMap
5. **手写方法会被生成覆盖**：目前靠区域外覆盖，后续加 skip 列表
6. **constructor 顺序**：默认构造函数在第一位，浏览器可能在末尾；优先级低
7. **对象值只展开一层**：嵌套对象只记 tag，无法自动还原
8. **symbol 值**（不是 symbol 键）无法自动还原，标 manual
9. **没有 vm2 侧 diff**：目前只验证“生成结果 vs 采集快照”的结构
10. **没有元数据 / realm / 版本分层**：快照会随 Chrome 升级互相覆盖
11. **main 一次只处理一个 target**：`TARGET` / `TARGET_FILE_PATH` 写死在顶部
12. **旧快照命名**：collector 输出 `<target>.json`，早期的 `<target>.Auto.json` 是旧 schema
13. **`window` / `document` 的 WindowProxy 语义**：`Reflect.ownKeys` / descriptor 行为特殊，需要单独处理
14. **proxy 干扰**：`vm_proxy.js` 的 `get` trap 读值会触发 getter，形态 diff 前要关 proxy

## 7. 踩坑记录

运行：

- `require` + 顶层 `await` + `package.json` 无 `"type"` → `ERR_AMBIGUOUS_MODULE_SYNTAX`；包进 async 函数
- ESM 里没有 `__dirname`
- `import { fs } from "fs"` 是错的
- `fs.statSync(path).isFile()` 在文件不存在时直接抛；用 `existsSync`
- `String.replace` 返回值必须重新赋值
- `writeFileSync` 的路径写错会生成奇怪文件名
- `readFileSync` 记得 `"utf8"`

采集：

- `for...in` 遍历数组拿到的是下标
- `Object.getOwnPropertyDescriptor` 参数是 `(对象, 键)`
- 读 `target[key]` 会触发 getter，可能抛 `Illegal invocation`
- accessor 没有 `value`；常量和函数都是 data 描述符
- `0` / `""` / `null` 不能做真值判断
- symbol 键用 `JSON.stringify` 会丢；控制台能展开是 DevTools 的行为
- `JSON.stringify[value]` 是属性访问，不是调用
- getter/setter 名字自带 `get ` / `set ` 前缀，length 0 / 1
- `Symbol.unscopables` 的值是 null 原型对象
- `Node.prototype` 直接进 JSON 会 `Illegal invocation`；Playwright 返回的是有损副本
- `Location.prototype` 几乎为空，成员在 `location` 实例上

生成：

- `function(){}` 有自有 `prototype`，原生方法没有；用方法简写
- 方法简写的 name 自动等于计算属性名
- `csvm.safefunction` 负责伪造 toString，用同一个 name 同时设置 name 和源码文本
- accessor 的 `name` 已经是 `"get xxx"` / `"set xxx"`，不要用属性 key 去拼
- 生成区域必须幂等，手写逻辑放区域外
