# DOM 解析插件设计（analysis_dom_plugin）

日期：2026-11-05 创建

> 2026-11-08：本文档只涉及 DOM 解析链路；浏览器 Plugin / MimeType 运行时已在同日移除，不影响这里的解析与生成流程。

把一份真实页面的 HTML 解析成框架运行时的 DOM 对象树。

```
src/dom.html  --analysis.js-->  page.json  --build_dom.js-->  src/csvm/browser/page.js
   (原始页面)       (解析)        (中间数据)        (代码生成)         (运行时建树)
```

`page.js` 在 `document.js` 之后加载，逐行调用 `csvm.DomGenerator(...)` 把树建出来。

## 1. 目录

```
plugin/analysis_dom_plugin/
  analysis.js     # dom.html -> page.json
  build_dom.js    # page.json -> src/csvm/browser/page.js
  page.json       # 中间产物，可读，用来核对
  解析设计.md
```

运行：

```
node plugin/analysis_dom_plugin/analysis.js
node plugin/analysis_dom_plugin/build_dom.js
```

## 2. 为什么用 parse5

Node 没有内置 HTML 解析。选 parse5 的理由是**树必须和浏览器一致**——检测脚本会比对 DOM 形状（`outerHTML` 长度、`childElementCount`、节点顺序），手写解析器在 `<table>` 补全、错误嵌套纠正这些地方很容易和浏览器分叉。

- `parse5.parse()` 是文档级解析，自动补 `<html><head><body>`、`<table>` 补 `<tbody>`
- 属性值**已解码实体**，`&lt;` 直接就是 `<`，不用自己写解码表
- 输出带 `sourceCodeLocation`（需要时开 `sourceCodeLocationInfo`）

## 3. 数据格式

每个节点都有 `tag`：

| `tag` | 含义 | 额外字段 |
|---|---|---|
| `div` / `meta` / … | 元素 | `attrs`、`children` |
| `#text` | 文本 | `text` |
| `#comment` | 注释 | `text` |
| `#documentType` | `<!DOCTYPE html>` | `name`、`publicId`、`systemId` |
| `#document` | 文档根 | `children` |

`#` 是**判别符**：HTML 合法标签名不含 `#`，不会冲突。其中 `#text` / `#comment` / `#document` 是浏览器 `nodeName` 的真实值；`#documentType` 是自己编的（浏览器的 doctype `nodeName` 是 `"html"`，会和 `<html>` 元素撞名）。

**文本节点必须保留**，包括纯缩进换行。这页里 782 个元素配了 1247 个文本节点，`<head>` 的 `childNodes` 就是 `TEXT,meta,TEXT,meta,...` 交错。丢掉文本，`childNodes.length`、`firstChild`、`innerHTML` 全对不上。

nodeType 对照：元素 1、文本 3、注释 8、文档 9、doctype 10、fragment 11。

## 4. analysis.js

```js
toNode(parse5节点) -> 我们的节点
```

要点：

- 注释、doctype **保留**，不要丢（`document.doctype`、`compatMode`、`childNodes` 都要用）
- `<template>` 的子节点在 `n.content.childNodes`，不在 `n.childNodes`
- 空文本节点（`""`）丢弃，空白文本保留

自检输出：

```
元素: 782 | 文本: 1247 | 注释: 1
doctype: html
#document 子节点: ["#documentType","html"]
目标 meta.content 长度: 5018
```

三个验收点：元素 782、doctype 与 html 平级、meta 的 content 是 5018 字符（实体解码后的长度）。

## 5. build_dom.js

遍历 page.json，前序 DFS，父节点先于子节点生成。

```js
var n1_documentType = csvm.DomGenerator("#documentType", {"name":"html","publicId":"","systemId":""}, document);
var n2_html = csvm.DomGenerator("html", {"lang":"zh-CN"}, document);
var n3_head = csvm.DomGenerator("head", {}, n2_html);
var n4_text = csvm.DomGenerator("#text", {"text":"\n  "}, n3_head);
```

规则：

- **根节点 `#document` 不生成**：它就是框架里已有的 `document`，只作为父节点传入。再建一个会导致 `document.documentElement.parentNode !== document`
- 变量名用 `n序号_标签`，稳定可读，方便 diff 和 grep
- 数据统一 `JSON.stringify`，文本里的换行、引号、反斜杠由它转义（手拼必炸）
- 每个节点一行，末尾换行

产物规模：2031 行（782 元素 + 1247 文本 + 1 注释 + 1 doctype）。

## 6. 运行时侧（框架里）

### DomGenerator

`src/csvm/tools/vm_memory.js`：

```js
csvm.DomGenerator(tag, data, parent) -> 节点对象
```

三步：

1. 造对象：元素查 `csvm.memory.Elements[tag]` 工厂；`#` 开头按 `nodeTypeOf` 选原型
2. 存数据：`csvm.memory.Dom.set(el, { tag, nodeType, data, parent, childNodes })`
3. 挂父上：`csvm.memory.Dom.get(parent).childNodes.push(el)`

**⚠️ 缺失接口不会报错，只会静默降级**

```js
var factory = csvm.memory.Elements[tag];
el = factory ? factory() : Object.create(P.element);   // P.element = HTMLElement.prototype
```

如果某个 `HTMLXxxElement.js` 没写、或者没加进 `Dom.node.js` 的加载顺序，`Elements[tag]` 就是 `undefined`，走兜底分支，**树照建，加载不报错**，但那个元素的类型是错的：

- `meta` 本该是 `[object HTMLMetaElement]`，降级后是 `[object HTMLElement]`
- 原型上没有 `content`，目标读 `.content` 得到 `undefined`
- 错误要等到**目标真正使用那个属性**才暴露，可能离现场很远

同理 `ensureProto` 里 `Text` / `Comment` / `DocumentType` 没写时也回退到 `Node.prototype`。

**排查手法**：建完树后扫一遍，看有没有本该是具体类型的元素停在 `HTMLElement`：

```js
var bad = [];
(function walk(el){
    var d = csvm.memory.Dom.get(el);
    if (d.tag === "meta" && Object.getPrototypeOf(el) !== HTMLMetaElement.prototype) bad.push(el);
    d.childNodes.forEach(walk);
})(document);
```

或者更省事：检查 `Object.keys(csvm.memory.Elements).length` 是不是等于"页面用到的标签种类数"。

### 两个容器

| 名字 | 内容 |
|---|---|
| `csvm.memory.Elements` | **tag → 工厂**（`Object.create(null)`，避免 `constructor` 之类的键命中 `Object.prototype`） |
| `csvm.memory.Dom` | **元素 → 内部数据**（WeakMap，键是元素对象） |

`data` 字段按 tag 装不同东西：元素是 attrs，文本/注释是 `{text}`，doctype 是 `{name, publicId, systemId}`。

### registerElement

```js
csvm.registerElement("div", HTMLDivElement);
```

各标签接口文件末尾调用一次。作用是：

```js
var proto = Ctor.prototype;                 // 注册时取一次
csvm.memory.Elements[tag] = function(){
    return Object.create(proto);
};
```

**必须缓存原型**：`Ctor.prototype` 是访问被 proxy 包过的构造函数，每次读都会进 get trap 记一行日志。不缓存的话 2000 个节点就是 2000 行噪音。

顺带一个好处：浏览器里 `X.prototype` 是 `writable:false, configurable:false`，不能整体替换；缓存之后目标即使执行 `HTMLDivElement.prototype = {}` 也不影响已登记的原型，行为恰好和浏览器一致。

### 原型缓存 ensureProto

`Node` / `HTMLElement` / `Text` / `Comment` / `DocumentType` 的原型各取一次，放在 `csvm.memory.Proto`，`DomGenerator` 直接用引用。

`Text` / `Comment` / `DocumentType` 三个接口还没写时回退到 `Node.prototype`（比回退到 `HTMLElement.prototype` 好，至少不会让文本节点长出 `getAttribute`）。

## 7. 踩坑记录

- **`fs.readFileSync` 用 `__dirname`**，不要用 CWD 相对路径
- **`Object.create()` 无参数会抛** `TypeError: Object prototype may only be an Object or null: undefined`，要 `Object.create(null)` 或 `Object.create(某个.prototype)`
- **元素不能 `new`**：`new Element()` 抛 `Illegal constructor`，浏览器里也一样。造元素用 `Object.create(具体标签.prototype)`
- **`X.prototype.__proto__ = X.prototype` 会抛** `TypeError: Cyclic __proto__ value`。批量写接口文件时最容易复制粘贴出这个
- **`tag[0] === "#"` 的判断只写一处**（`nodeTypeOf`），散在各处必然漏
- **日志阶段**：`csvm.memory.phase` 由 `index.js` 在框架和目标之间切换，`printInit:false` 时加载期日志不显示
- **接口缺失是静默的**：没注册的标签会回退到 `HTMLElement.prototype`，不报错、不警告，只体现为 `toString` 变成 `[object HTMLElement]`、专属属性读到 `undefined`。写新标签接口后忘了加进 `Dom.node.js`，就是这个问题
